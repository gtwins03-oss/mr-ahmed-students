# دليل التشغيل — نظام إدارة الطلاب والتنبيهات

دليل عملي من الصفر: تنصّب النظام، تشغّله، وتجرّب الدورة الكاملة في خمس دقايق.
كل أمر مكتوب هنا موجود فعلاً في المشروع ويشتغل زي ما هو — انسخه والصقه في PowerShell.

**مسار المشروع على الجهاز ده:** `d:\programming\mr ahmed`

| | |
|---|---|
| الواجهة (التطوير) | <http://localhost:5173> |
| الـ API | <http://localhost:4000> |
| فحص الحالة | <http://localhost:4000/api/health> |

افتح **PowerShell** واكتب:

## ٢. التشغيل المحلي

نفّذ الأوامر دي **بالترتيب**، كل أمر لوحده، من نافذة PowerShell واحدة.

### الخطوة ١ — ادخل مجلد المشروع

```powershell
cd "d:\programming\mr ahmed"
```

العلامتين `"` مهمين لأن في المسار مسافة.

### الخطوة ٢ — أدوات الجذر *(≈ ١٥ ثانية)*

```powershell
npm install
```

بينزّل حزمة واحدة بس هي `concurrently`، اللي بتشغّل الخادم والواجهة مع بعض في نفس النافذة.

**المتوقع:** سطر زي `added 1 package in 3s`.

### الخطوة ٣ — ملف إعدادات الخادم *(ثانية واحدة)*

```powershell
if (-not (Test-Path server\.env)) { Copy-Item server\.env.example server\.env }
```

بينسخ `server/.env.example` إلى `server/.env` لو مش موجود. الملف ده فيه مسار قاعدة البيانات، منفذ الـ API، مفتاح توقيع رموز الدخول (`JWT_SECRET`)، وبيانات حساب المالك.

**المتوقع:** مفيش أي مخرجات — الصمت معناه إنه اشتغل. للتأكد: `Test-Path server\.env` لازم يرد `True`.

> `server/.env` مستبعَد من Git عمداً (شوف `.gitignore`)، فهو مش بيتنقل مع نسخة المشروع ولا بيتسرّب لأي حد.

### الخطوة ٤ — التنصيب الكامل وتجهيز قاعدة البيانات *(من دقيقتين لـ ٥ حسب النت)*

```powershell
npm run setup
```

الأمر ده بيعمل تلات حاجات ورا بعض:

1. `npm install --prefix server` — حزم الخادم (Express، Prisma، zod، socket.io …).
2. `npm install --prefix web` — حزم الواجهة (React، Vite، Tailwind، Capacitor …).
3. `npm run db:reset` — يعني `db:push` (ينشئ الجداول من `server/prisma/schema.prisma`) ثم `db:seed` (يملأ الإعدادات والقوالب والبيانات التجريبية وحساب المالك).

**المتوقع في آخر التنفيذ** — ملخّص عربي وتنبيه أمني بالشكل ده:

  📅 مواعيد أسبوعية:    7 (حصة يومية 16:00 - 17:30)

  🔗 الاشتراكات:        6
  🔐 المستخدمون:        1 (المالك: ahmed — تم إنشاؤه الآن)

  ══════════════════════════════════════════════════════════
  ⚠️   تنبيه أمني مهم — اقرأ هذا السطر قبل أي شيء آخر

### الخطوة ٥ — شغّل النظام

```powershell
npm run dev
```

بيشغّل **عمليتين في نفس النافذة** عن طريق `concurrently`، وكل سطر بيظهر ومعاه اسم مصدره:

| الاسم في الطرفية | اللون | إيه هي | العنوان |
|---|---|---|---|
| `API` | أزرق | الخادم: Express + Prisma + المهام المجدولة + قائمة الإرسال | <http://localhost:4000> |
| `WEB` | بنفسجي | الواجهة: Vite في وضع التطوير | <http://localhost:5173> |

**المتوقع** من ناحية الخادم:

```
  ╭──────────────────────────────────────────────╮
  │        نظام إدارة الطلاب والتنبيهات          │
  ╰──────────────────────────────────────────────╯
  ✅ الخادم يعمل على: http://localhost:4000
  🩺 فحص الحالة:     http://localhost:4000/api/health
  📱 من الشبكة المحلية: http://192.168.1.10:4000
  🖥️  واجهة التطوير:   http://localhost:5173
  🔌 التحديثات الفورية مفعّلة

  ⏰ تم تفعيل المهام المجدولة
```

ومن ناحية الواجهة سطر Vite المعتاد: `Local: http://localhost:5173/`.

- **افتح ٥١٧٣ مش ٤٠٠٠.** المنفذ ٤٠٠٠ هو الـ API لوحده. Vite بيمرّر كل طلبات `/api` من ٥١٧٣ إلى ٤٠٠٠ تلقائياً، فمفيش أي إعداد إضافي.
- **النافذة لازم تفضل مفتوحة.** Ctrl + C بيوقّف العمليتين. صغّرها ولا تقفلها.
- سطر `📱 من الشبكة المحلية` هو العنوان اللي هتكتبه في تطبيق الموبايل لاحقاً.

### الخطوة ٦ — سجّل الدخول

افتح **<http://localhost:5173>**:

| الحقل | القيمة |
|---|---|
| اسم المستخدم | `ahmed` |
| كلمة المرور | `admin123` |

> ## ⚠️ غيّر كلمة المرور دلوقتي حالاً
>
> `admin123` كلمة مرور **افتراضية معروفة ومكتوبة في ملف عام**. أي حد على نفس شبكة الواي فاي — ولو حتى ضيف — يقدر يفتح العنوان ويدخل بيها على كل بيانات طلابك وأرقام أولياء أمورهم.
>
> **بعد أول دخول على طول:** **الإعدادات ← الحساب** ← اكتب كلمة المرور الحالية والجديدة ← **حفظ**. أقل طول مسموح ٦ أحرف، والمفروض تختار أطول من كده بكتير.
>
> ولو ناوي تنشر النظام على الإنترنت، غيّر كمان `JWT_SECRET` في `server/.env` لنص عشوائي طويل — من غير كده أي حد يقدر يزوّر رمز دخول ويدخل كمالك.

### البديل: `start.bat` بضغطة مزدوجة

في جذر المشروع فيه ملف **`start.bat`**. دبل كليك عليه بيعمل اللي فوق كله لوحده: بيتأكد من وجود `npm`، وينفّذ `npm install` لو `node_modules` ناقصة، و `npm run setup` لو دي أول مرة، وبعدين `npm run dev`.

> فرق واحد بس: `start.bat` **مش** بينسخ `.env.example` إلى `.env`. نفّذ أمر الخطوة ٣ مرة واحدة قبل ما تستخدمه.

### التشغيل اليومي بعد كده

```powershell
cd "d:\programming\mr ahmed"
npm run dev
```

بس كده. مفيش `npm install` ولا `setup` تاني إلا لو غيّرت الحزم أو شكل الجداول.

## ٣. جولة تجريبية في ٥ دقايق

البيانات التجريبية اتحطّت بالفعل مع `npm run setup`: مجموعة **«مجموعة تجريبية - ٣ ثانوي»** مادتها الرياضيات، فيها **٦ طلاب** بأرقام أولياء أمور وهمية، و**٧ مواعيد أسبوعية** — واحد لكل يوم من **٤:٠٠ م لـ ٥:٣٠ م** — عشان تلاقي حصة جاهزة مهما كان اليوم اللي بتجرّب فيه.

نفّذ الخطوات دي بالترتيب.

### ١) علّم غياب

من القايمة الجانبية اضغط **الحضور**. المفروض تلاقي المجموعة التجريبية بتاريخ النهارده وتحتها كشف الستة طلاب.

اضغط زر **غائب** جنب أول طالب (**أحمد محمود عبد الرحمن**).

**الضغطة بتتحفظ فوراً — مفيش زر «حفظ»**. هتلاحظ حاجتين في نفس اللحظة:

- العدّاد فوق الكشف بقى `غائب ١`.
- شريط أخضر ظهر مكتوب فيه **«تم إضافة ١ رسالة إلى قائمة الإرسال»** وجنبه رابط **«فتح قائمة الإرسال»**.

الأزرار الأربعة: **حاضر · غائب · متأخر · بعذر**. الرسائل بتتولّد للغياب والتأخير بس، والتأخير مطفي افتراضياً من الإعدادات.

### ٢) افتح قائمة الإرسال

اضغط الرابط الأخضر، أو **قائمة الإرسال** من القايمة الجانبية (هتلاقي شارة برقم الرسائل المعلّقة جنبها).

هتلاقي رسالة واحدة في تبويب **قيد الانتظار**، ونصّها العربي الكامل ظاهر قدامك:

```
السلام عليكم ورحمة الله وبركاته
عزيزي ولي أمر الطالب/ة: أحمد محمود عبد الرحمن

نود إحاطتكم علماً بأن الطالب/ة تغيّب اليوم عن حصة الرياضيات
📅 التاريخ: ...
🕐 الموعد: ٤:٠٠ م

نرجو المتابعة والتواصل معنا لأي استفسار.
مع خالص التقدير،
الأستاذ أحمد
```

تحت كل رسالة معلّقة: **فتح واتساب** · **تم الإرسال ✓** (تعليم يدوي) · **تعديل** (تغيير نص الرسالة دي بس) · **تجاهل**.

### ٣) اضغط «فتح واتساب»

هيفتح تبويب جديد على **واتساب ويب** على محادثة رقم ولي الأمر (`+201001234567`) **والرسالة مكتوبة جاهزة في خانة الكتابة**. مش باقي غير إنك تضغط إرسال جوّه واتساب. الرسالة في النظام بتتعلّم **تم الإرسال** تلقائياً بمجرد ما تضغط الزر.

> أول مرة واتساب ويب هيطلب مسح رمز QR من موبايلك — ده إجراء واتساب نفسه مش من البرنامج.
> والأرقام التجريبية وهمية، فمتستغربش لو قال «الرقم غير مسجّل».

### ٤) علّم نفس الطالب تاني — وشوف إن مفيش رسالة مكرّرة

ارجع **الحضور**، اضغط **حاضر** لنفس الطالب، وبعدين **غائب** تاني. افتح قائمة الإرسال… **لسه رسالة واحدة بس**، مفيش تكرار.

> **ليه؟** كل رسالة بتتخزّن بمفتاح فريد `dedupeKey` — للغياب شكله `ABSENT:{رقم الحصة}:{رقم الطالب}` — والعمود ده فريد في قاعدة البيانات، فمهما حفظت كشف الحضور مية مرة، ولي الأمر عمره ما يوصله نفس التنبيه مرتين.

### ٥) أنشئ اختبار وسجّل درجة أقل من ٦٠٪

- اضغط **الدرجات** ← **اختبار جديد**.
- **المجموعة:** المجموعة التجريبية · **العنوان:** «اختبار الوحدة الأولى» · **الدرجة الكاملة:** `20` · **التاريخ:** سيبه النهارده.
- اضغط **إنشاء ثم إدخال الدرجات** — هتروح على شبكة إدخال الدرجات.
- اكتب لأول طالب **`10`** (يعني ٥٠٪ — تحت الحد ٦٠٪) ولطالب تاني **`18`** (٩٠٪).
- اضغط **حفظ الدرجات**.

افتح **قائمة الإرسال** → هتلاقي **تنبيه مستوى** جديد للطالب صاحب الـ ٥٠٪ **بس**، وفيه الدرجة والنسبة والحد المطلوب. صاحب الـ ٩٠٪ مفيش له رسالة.

> الخانة اللي تسيبها فاضية معناها **«لم يؤدِّ الاختبار»** — مش صفر، ومش بتتحسب في المتوسط ولا بتنتج رسالة.

### ٦) غيّر العتبة من الإعدادات

- **الإعدادات ← الإعدادات العامة** ← غيّر **«حد الدرجة المنخفضة»** من `60` إلى `95` ← **حفظ**.
- ارجع **الدرجات** ← **اختبار جديد** تاني (نفس المجموعة، درجة كاملة `20`) ← سجّل لصاحب الـ ٩٠٪ درجة **`18`** ← **حفظ الدرجات**.
- دلوقتي ٩٠٪ بقت تحت ٩٥٪ → هتلاقي تنبيه مستوى جديد له في قائمة الإرسال.

> العتبة بتتطبّق **وقت حفظ الدرجات**، فلازم تسجّل الدرجة **بعد** ما تغيّر الإعداد.
> ولازم اختبار **جديد** كمان، لأن `dedupeKey` بتاع تنبيه المستوى هو `LOW_GRADE:{رقم الاختبار}:{رقم الطالب}` — نفس الاختبار مش هيولّد تنبيه تاني لنفس الطالب أبداً.

### ٧) افتح سجل النشاط وشوف كل ده متسجّل

من القايمة الجانبية (قسم المالك) اضغط **سجلّ النشاط**. هتلاقي كل خطوة عملتها دلوقتي مكتوبة بجملة عربية كاملة، الأحدث فوق:

```
إعدادات    إعدادات   غيّر عتبة الدرجات من ٦٠٪ إلى ٩٥٪
رصد درجات  درجة      سجّل درجة "سارة خالد إبراهيم": ١٨ من ٢٠ في اختبار الوحدة الأولى
إضافة      اختبار    أنشأ اختبار قصير "اختبار الوحدة الأولى" للمجموعة التجريبية من ٢٠ درجة
رسالة      رسالة     أرسل تنبيه غياب إلى ولي أمر "أحمد محمود عبد الرحمن"
تسجيل حضور حضور      غيّر حضور "أحمد محمود عبد الرحمن" من حاضر إلى غائب
تسجيل حضور حضور      علّم "أحمد محمود عبد الرحمن" غائب في حصة الرياضيات
تسجيل دخول مستخدم    سجّل «الأستاذ أحمد» الدخول إلى النظام
```

كده تكون جرّبت الدورتين الكاملتين: **حضور ← تنبيه ← ولي الأمر**، و **درجة ← تنبيه ← ولي الأمر**، وشوفت إن الاتنين متسجّلين.

## ٤. المستخدمون والصلاحيات

في النظام **دورين بس**، ومفيش غيرهم:

| الدور | الاسم في الواجهة | مين ده |
|---|---|---|
| `OWNER` | **صاحب الحساب** | الأستاذ أحمد — الحساب اللي اتعمل مع `db:seed`. |
| `ASSISTANT` | **مساعد** | أي حد بيساعد في إدخال البيانات: سكرتير، مدرّس مساعد، حد من الأسرة. |

### إيه اللي المساعد يعمله وإيه اللي لأ

**القاعدة باختصار: المساعد بيعمل كل حاجة في البيانات، وممنوع بس من شاشتين إداريتين.**

| الشاشة / العملية | صاحب الحساب | المساعد |
|---|:---:|:---:|
| لوحة التحكم | ✅ | ✅ |
| الطلاب — إضافة وتعديل وحذف | ✅ | ✅ |
| المجموعات والمواعيد الأسبوعية | ✅ | ✅ |
| الحضور — تسجيل وتعديل | ✅ | ✅ |
| الدرجات — إنشاء اختبارات ورصد درجات | ✅ | ✅ |
| قائمة الإرسال — إرسال، تعديل نص رسالة، تجاهل، إعادة محاولة | ✅ | ✅ |
| قوالب الرسائل — تعديل النصوص | ✅ | ✅ |
| الإعدادات — بيانات المُدرِّس، العتبة، ساعات الهدوء، مزوّد الإرسال | ✅ | ✅ |
| تغيير كلمة مرور **حسابه هو** | ✅ | ✅ |
| **سجلّ النشاط** (`/api/audit`) | ✅ | ❌ |
| **المستخدمون** (`/api/users`) | ✅ | ❌ |

المنع مش شكلي: عنصر القايمة **مش بيظهر** للمساعد أصلاً، ولو كتب `/audit` أو `/users` في العنوان بيترجع للوحة التحكم من غير رسالة «ممنوع» (عشان مايتأكدش إن الصفحة موجودة)، ولو حاول ينده الـ API مباشرة بيرد **403** بنفس الشكل سواء الرقم اللي بيسأل عنه موجود أو لأ.

### إزاي تضيف مساعد

1. من القايمة الجانبية (قسم المالك) اضغط **المستخدمون**.
2. اضغط **مستخدم جديد**.
3. املأ:
   - **الاسم الكامل** — زي «سارة محمد»، ده اللي هيظهر في سجل النشاط.
   - **اسم المستخدم** — حروف إنجليزية وأرقام من ٣ لـ ٣٢ خانة، النقطة والشرطة مسموحين. مثال: `sara` أو `assistant1`.
   - **الصلاحية** — **مساعد**.
   - **كلمة المرور** — ٦ أحرف على الأقل.
4. **حفظ**.

بعد كده تقدر من نفس الصفحة: **تعديل** بياناته، **إعادة تعيين كلمة المرور** (من غير ما تعرف القديمة)، **إيقاف** الحساب مؤقتاً، أو **حذفه** نهائياً.

| الحماية | التفاصيل |
|---|---|
| **لازم يفضل مالك واحد نشط** | مش هينفع تحذف أو توقف أو تنزّل صلاحية آخر حساب مالك نشط — الرد `يجب أن يبقى صاحب حساب واحد نشط على الأقل`. ده بيمنع إنك تقفل على نفسك الباب من بره. |
| **مفيش تعديل على نفسك بالغلط** | ما ينفعش توقف حسابك أو تغيّر صلاحيتك أو تحذف نفسك. |
| **الإيقاف فوري** | البيانات بتتقرا من قاعدة البيانات مع **كل** طلب، مش من رمز الدخول. أول ما توقف حساب مساعد، أول طلب منه بيرجع 401 برسالة `تم إيقاف هذا الحساب` — مش مستني الرمز يخلص صلاحيته بعد ٣٠ يوم. |
| **كلمات المرور مش مخزّنة** | متخزّنة كـ bcrypt hash، والعمود ده مش بيخرج من الخادم أبداً ومش بيتكتب في سجل النشاط. |
| **التاريخ بيفضل بعد الحذف** | حذف مستخدم مش بيمسح سجل نشاطه — كل صف محتفظ باسم صاحبه وقت التنفيذ. |

### نسيت كلمة مرور المالك؟

مفيش استعادة تلقائية. الحل: عدّل `OWNER_USERNAME` في `server\.env` لاسم جديد، ثم:

```powershell
npm run --prefix server db:seed
```

بيتعمل حساب مالك جديد بكلمة المرور اللي في `OWNER_PASSWORD`. ادخل بيه، وبعدين أعد تعيين كلمة مرور الحساب القديم من صفحة **المستخدمون**.

> `db:seed` **مش** بيغيّر كلمة مرور حساب موجود ولا بيمسح بياناتك — ده مقصود.

## ٥. سجل النشاط

صفحة **سجلّ النشاط** بتجاوب على سؤال واحد: **مين عمل إيه وامتى؟**

### إيه اللي بيتسجّل

كل عملية كتابة في النظام بتكتب صف في السجل، وكل صف فيه:

| الحقل | إيه هو |
|---|---|
| **المستخدم** | الاسم والصلاحية **وقت التنفيذ** (مأخوذين نسخة، فحتى لو الحساب اتغيّر اسمه أو اتحذف السجل يفضل مفهوم). |
| **الوقت** | تاريخ وساعة العملية. |
| **نوع الإجراء** | تسجيل دخول · إضافة · تعديل · حذف · تسجيل حضور · رصد درجات · رسالة · إعدادات. |
| **النوع** | طالب · مجموعة · حصة · حضور · اختبار · درجة · رسالة · قالب رسالة · إعدادات · مستخدم. |
| **الوصف** | جملة عربية جاهزة: `غيّر حضور "أحمد محمود" من حاضر إلى غائب`. |
| **قبل / بعد** | لقطة JSON بالقيم القديمة والجديدة — تفتحها بالضغط على الصف. |
| **عنوان الجهاز (IP)** | تقريبي وللعرض بس. |

**اللي مش بيتسجّل أبداً:** أي كلمة مرور، أي hash، وأي `apiToken` أو `authToken` بتاع مزوّد الرسائل. أي مفتاح اسمه فيه كلمة زي `password` أو `token` أو `secret` قيمته بتتحوّل لـ `«محجوب»` قبل ما تتكتب.

### للمالك فقط

- عنصر **سجلّ النشاط** في القايمة **مش موجود** أصلاً لحساب المساعد.
- `/api/audit` بيرد **403** لأي حساب غير المالك، من غير ما يلمس قاعدة البيانات.
- **السجل للقراءة فقط.** مفيش `POST` ولا `PATCH` ولا `DELETE` — ومش المفروض يتضاف. سجل صاحبه يقدر يعدّله مش سجل.

### إزاي تفلتره

فوق الجدول فيه شريط فلاتر:

| الفلتر | الاستخدام |
|---|---|
| **بحث في السجل** | نص حر بيدوّر في وصف العملية وفي اسم المستخدم — مثلاً اسم طالب معيّن. |
| **المستخدم** | كل المستخدمين، أو حساب واحد بالذات. القايمة بتعرض بس الحسابات اللي ليها نشاط فعلاً. |
| **نوع الإجراء** | حضور بس، أو حذف بس، أو تسجيلات الدخول… |
| **النوع** | طالب، مجموعة، رسالة… |
| **من تاريخ / إلى تاريخ** | فترة محددة، والطرفين داخلين في النتيجة. |

الفلاتر بتتجمع مع بعض. مثال عملي: **نوع الإجراء = حذف** + **من تاريخ = أول الشهر** بيديك كل حاجة اتمسحت الشهر ده ومين مسحها.

## ٦. الشبكة الضعيفة

النظام متعامل مع فكرة إن المعلّم بيسجّل الحضور من موبايله في مكان الشبكة فيه ضعيفة — مش من لابتوب على شبكة ممتازة.

### إيه اللي بيحصل لما الاتصال يقطع

1. **شريط أصفر بيظهر تحت العنوان:** «لا يوجد اتصال — سيتم حفظ تعديلاتك وإرسالها تلقائياً»، وجنبه رابط **عنوان الخادم** لو المشكلة في العنوان أصلاً.
2. **الشاشات بتفضل شغّالة** — القراءة بتتم من الذاكرة المؤقتة، فمش هتلاقي صفحة فاضية ولا دوّامة تحميل.
3. **الضغط على «غائب» مش بيفشل** — التعديل بيتحط في طابور مؤقّت بدل ما يرمي خطأ.
4. **أول ما الشبكة ترجع** الطابور بيتفرّغ لوحده، وبيظهر شريط أزرق «جارٍ رفع تعديلين…» وبعده شريط أخضر **«تمت المزامنة»** لتلات ثواني، وبعدين الشريط بيختفي خالص.

كمان: أي طلب بيفشل بسبب الشبكة أو خطأ خادم (5xx) بيتعاد **٣ مرات** بفواصل متزايدة (١ ثانية، ٢، ٤ … بحد أقصى ١٠ ثواني). الأخطاء اللي هي إجابة فعلية — زي ٤٠٠ أو ٤٠٣ — **مش** بتتعاد، لأن إعادتها مش هتغيّر حاجة.

### فين التعديلات المعلّقة بالظبط

في **`localStorage`** بتاع المتصفح (أو الـ WebView) تحت المفتاح **`tutor.query-cache`**، ومعاها آخر نسخة من البيانات المقروءة (صلاحيتها ٢٤ ساعة). يعني لو قفلت التطبيق والاتصال راجع، البيانات بتظهر فوراً من غير انتظار.

### اللي **مش** مدعوم — بصراحة

| مش مدعوم | التفاصيل |
|---|---|
| **العمل بدون خادم أصلاً** | ده مش تطبيق offline-first. الطابور بيتحمّل انقطاع مؤقّت — مش بديل عن وجود خادم شغّال. أول تشغيل بدون شبكة = شاشة تسجيل دخول مش هتعدّي. |
| **تسجيل الدخول بدون اتصال** | لازم اتصال بالخادم. مفيش وضع «ضيف». |
| **التعديلات المعلّقة بعد قفل التطبيق تماماً** | التعديلات المتوقّفة بتتخزّن على الجهاز، **لكن لو قفلت التطبيق قبل ما الشبكة ترجع فهي مش بتتبعت لوحدها لما تفتحه تاني** — بتفضل ظاهرة كمعلّقة بس. **الخلاصة العملية:** لو الشبكة قطعت وأنت بتسجّل حضور، سيب التطبيق مفتوح لحد ما يظهر شريط **«تمت المزامنة»**. |
| **فتح واتساب بدون اتصال** | زر «فتح واتساب» بيحتاج واتساب نفسه، والرسالة بتتبعت من واتساب مش من النظام. |
| **حل تعارض التعديلات** | لو أنت ومساعدك عدّلتم نفس الطالب في نفس اللحظة، آخر حفظ هو اللي بيثبت. مفيش شاشة «اختار النسخة الصح». السجل بيوضّح مين عمل إيه. |
| **التحديثات الفورية أثناء الانقطاع** | التحديث الفوري (socket) بيقف وقت الانقطاع ويرجع لوحده. البيانات بتتحدّث كمان تلقائياً كل ما ترجع للتبويب أو ترجع الشبكة. |

## ٩. تشغيل الإرسال التلقائي (اختياري)

في الوضع الافتراضي (**WA_LINK**) كل رسالة محتاجة ضغطتين: «فتح واتساب» ثم «إرسال» جوّه واتساب. لو عايز الرسائل تطلع لوحدها، فيه مزوّد اسمه **Green API** بيتوصّل برقم الواتساب بتاعك.

1. اعمل حساب على **[green-api.com](https://green-api.com)** وأنشئ **Instance** (فيه باقة مجانية للتجربة).
2. اعرض **رمز QR** من لوحة تحكم Green API وامسحه من واتساب الأستاذ: **واتساب ← الأجهزة المرتبطة ← ربط جهاز**. الحالة لازم تبقى `authorized`.
3. انسخ **`idInstance`** و **`apiTokenInstance`**.
4. في التطبيق: **الإعدادات ← مزوّد الإرسال** ← غيّر **المزوّد** إلى **Green API** ← الصق القيمتين ← **حفظ**. (`apiUrl` سيبها فاضية.)
5. اكتب رقمك في **«اختبار الإرسال — رقم الهاتف»** واضغط **اختبار الإرسال**. لازم تحفظ **قبل** الاختبار.
6. لو وصلتك الرسالة → خلاص. زر **«إرسال الكل تلقائياً»** هيظهر في قائمة الإرسال، والنظام كمان بيفرّغ القائمة لوحده كل دقيقتين.

| الضمان | التفاصيل |
|---|---|
| **ساعات الهدوء** | من **١٠:٠٠ م لـ ٨:٠٠ ص** مفيش إرسال تلقائي. الرسائل بتستنى لحد ما الوقت يعدّي. (الإرسال اليدوي شغّال دايماً.) |
| **تهدئة الإرسال** | فاصل بين كل رسالة والتانية — مفيش دفعة مفاجئة تشدّ انتباه واتساب. |
| **منع التكرار** | `dedupeKey` بيمنع أصلاً وجود نفس الرسالة مرتين في الطابور. |
| **سجل كامل** | كل رسالة صف في قاعدة البيانات قبل ما تتبعت: نصّها، حالتها، وسبب فشلها لو فشلت. |

> ### ⚠️ خطر حظر الرقم
> **Green API بوابة غير رسمية** بتتصرّف كأنها جهاز مرتبط بواتساب بتاعك، وده **مخالف لشروط استخدام واتساب**. فيه **احتمال حقيقي إن رقمك يتحظر** — مؤقتاً أو نهائياً.
>
> - **جرّب على رقم تاني** مش رقمك الأساسي.
> - **WA_LINK آمن ١٠٠٪** ومفيهوش أي خطر حظر، لأن الإرسال بيتم من واتساب بتاعك بإيدك زي أي رسالة عادية. لو مش متأكد — سيبه.
> - البديل الرسمي المعتمد لو الشغل كبر هو **Twilio (WhatsApp Business API)**، مدعوم في نفس الشاشة، بس محتاج حساب أعمال معتمد ومصاريف شهرية.

## ١٠. البيانات والنسخ الاحتياطي

### فين البيانات؟

كل حاجة — الطلاب، المجموعات، الحضور، الدرجات، الرسائل، الإعدادات، سجل النشاط — في **ملف واحد**:

```
server\data\tutor.db
```

عايز تنقل النظام لجهاز تاني؟ انسخ الملف ده وحطه في نفس المكان. خلاص.

نسخة احتياطية يدوية دلوقتي:

```powershell
Copy-Item "d:\programming\mr ahmed\server\data\tutor.db" "$env:USERPROFILE\Desktop\tutor-backup.db"
```

### النسخ الاحتياطي التلقائي

طول ما الخادم شغّال، فيه مهمة بتشتغل **كل يوم ٢:٣٠ صباحاً**: بتنسخ قاعدة البيانات إلى `server\backups\tutor-YYYY-MM-DD.db` وبتحتفظ بـ **آخر ٣٠ نسخة**.

> النسخ دي جوّه نفس مجلد المشروع، فهي **مش** حماية من عطل الهارد. انسخ `server\backups\` من وقت للتاني على فلاشة أو على Google Drive.

لاستعادة نسخة: اقفل النظام (Ctrl + C) ثم:

```powershell
cd "d:\programming\mr ahmed"
Copy-Item server\backups\tutor-2026-09-05.db server\data\tutor.db -Force
npm run dev
```

### المهام المجدولة كلها

| الوقت | المهمة |
|---|---|
| **٦:٠٠ ص** يومياً (وكمان عند كل تشغيل للخادم) | إنشاء حصص اليوم من الجدول الأسبوعي. |
| **كل دقيقتين** | تفريغ قائمة الإرسال (مش بتعمل حاجة في وضع `WA_LINK` أو أثناء ساعات الهدوء). |
| **٦:٠٠ م يوم ١** من كل شهر | تجهيز التقارير الشهرية لأولياء الأمور عن الشهر اللي فات. |
| **٢:٣٠ ص** يومياً | النسخ الاحتياطي لقاعدة البيانات. |

### تصفير كل حاجة والبدء من جديد

**بيمسح كل البيانات نهائياً.** اقفل النظام (Ctrl + C) ثم:

```powershell
cd "d:\programming\mr ahmed"
Remove-Item server\data\tutor.db* -Force
npm run db:reset
```

> النجمة في `tutor.db*` مقصودة — بتشيل معاها ملفات SQLite المساعدة (`-journal` / `-wal`).
> ولاحظ إن ده **بيرجّع البيانات التجريبية**، فهو مش طريق للتخلّص منها — هو طريق للرجوع لنقطة صفر معروفة.

### إزالة البيانات التجريبية

البيانات التجريبية بيانات عادية زي أي بيانات، مفيش أمر خاص ليها. امسحها من الواجهة: **الطلاب** ← حذف الستة طلاب (الملاحظة عندهم مكتوب فيها «طالب تجريبي»)، ثم **المجموعات** ← حذف «مجموعة تجريبية - ٣ ثانوي».

> **الحذف من الواجهة = تعطيل (soft delete)، مش محو نهائي.** الطالب بيختفي من الكشوف والحصص الجديدة، لكن تاريخ حضوره ودرجاته بيفضل موجود عشان التقارير ما تبوظش — وده مقصود.
> عايز محو نهائي؟ `npm run --prefix server db:studio` واحذف الصفوف من جدولَي `Student` و `ClassGroup`.
