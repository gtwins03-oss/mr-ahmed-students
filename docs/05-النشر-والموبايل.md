# دليل النشر وتطبيق الموبايل

الدليل ده بياخدك من «النظام شغّال على اللابتوب» إلى «النظام شغّال على الإنترنت وفيه تطبيق على تليفوني».

**مش مضطر تعمل كل ده.** لو النظام شغّال على جهاز واحد في السنتر وأنت مبسوط كده — سيبه. اقرأ الدليل ده لما تحتاج واحدة من التلاتة دول:

- عايز تدخل على النظام من بيتك أو من أي مكان، مش من اللابتوب بس.
- عايز مساعدك يشتغل من جهازه في نفس الوقت.
- عايز أيقونة على شاشة تليفونك بدل ما تفتح المتصفح كل مرة.

> **ملحوظة مهمة قبل ما تبدأ:** تطبيق الأندرويد **مش** بيحتوي على النظام جوّاه — هو واجهة بتتكلم مع الخادم. يعني لازم يكون فيه خادم شغّال في مكان ما: إمّا لابتوبك على نفس شبكة الواي فاي (وده كافي تماماً وببلاش)، أو استضافة على الإنترنت (لو عايز تشتغل من بره السنتر).

**الترتيب المنطقي:** قاعدة البيانات ← الخادم ← التطبيق.

## ١. رفع قاعدة البيانات على Supabase

محلياً قاعدة البيانات ملف SQLite واحد. الملف ده ممتاز على جهاز واحد، لكنه مش هينفع مع استضافة سحابية بتعيد تشغيل نفسها وبتمسح الملفات المؤقتة. الحل: **PostgreSQL** على [Supabase](https://supabase.com) — فيه باقة مجانية كفاية أكتر من اللازم لسنتر.

كل الجداول في المشروع متصمّمة تشتغل على المزوّدين الاتنين (أعمدة الحالة نصوص مش enums، مفيش مصفوفات، مفيش أنواع خاصة بـ Postgres)، فالتحويل **سطر واحد مش إعادة كتابة**.

### الخطوة ١ — أنشئ المشروع

1. ادخل [supabase.com](https://supabase.com) واعمل حساب (بـ GitHub أو بالإيميل).
2. **New project**:
   - **Name:** أي اسم، مثلاً `mr-ahmed`.
   - **Database Password:** **اكتب كلمة مرور قوية واحفظها فوراً في مكان آمن** — Supabase مش هيعرضها تاني، وهي جزء من رابط الاتصال.
   - **Region:** اختار الأقرب لمصر — `Central EU (Frankfurt)` عادةً أسرع اختيار.
3. استنى دقيقة–اتنين لحد ما المشروع يجهز.

### الخطوة ٢ — انسخ رابط الاتصال

من داخل المشروع: **Project Settings ← Database ← Connection string ← URI**.

هتلاقي حاجة شكلها كده:

```
postgresql://postgres:[YOUR-PASSWORD]@db.abcdefghijklm.supabase.co:5432/postgres
```

- بدّل `[YOUR-PASSWORD]` بكلمة المرور اللي كتبتها في الخطوة ١ (من غير الأقواس المربّعة).
- لو كلمة المرور فيها رموز خاصة (`@` أو `#` أو `/`) لازم تتكتب بترميز URL — أسهل حل إنك تختار كلمة مرور بحروف وأرقام بس.
- **استخدم المنفذ `5432` (الاتصال المباشر)** مع `prisma db push`، مش منفذ الـ pooler `6543` — الـ pooler مش بيتعامل كويس مع أوامر تعديل الجداول.

### الخطوة ٣ — حطه في `DATABASE_URL`

افتح `server\.env` وبدّل سطر قاعدة البيانات:

```ini
# DATABASE_URL="file:../data/tutor.db"
DATABASE_URL="postgresql://postgres:PASSWORD@db.PROJECT.supabase.co:5432/postgres?sslmode=require"
```

`?sslmode=require` في الآخر **مطلوبة** — Supabase مش بيقبل اتصال غير مشفّر.

### الخطوة ٤ — حوّل Prisma ثم جهّز الجداول

من جذر المشروع، بالترتيب:

```powershell
npm run --prefix server db:use-postgres
```

بيغيّر سطر واحد في `server/prisma/schema.prisma` من `provider = "sqlite"` إلى `provider = "postgresql"` ويعيد توليد عميل Prisma. **المتوقع:**

```
  📄 الملف:     d:\programming\mr ahmed\server\prisma\schema.prisma
  ⬅️  قبل:      provider = "sqlite"
  ➡️  بعد:      provider = "postgresql"

  ⚠️  لا تنسَ تحديث DATABASE_URL في ملف .env:
```

```powershell
npm run --prefix server db:push
```

بينشئ كل الجداول على Supabase. **المتوقع:** `Your database is now in sync with your Prisma schema.`

```powershell
npm run --prefix server db:seed
```

بيضيف الإعدادات وقوالب الرسائل العربية وحساب المالك والبيانات التجريبية. **المتوقع:** نفس الملخّص العربي بتاع التشغيل المحلي.

### الخطوة ٥ — اتأكد إنه اشتغل

```powershell
npm run dev
```

سجّل دخول عادي. لو الشاشات شغّالة يبقى النظام بقى بيقرا ويكتب على Supabase.

للتأكد من الناحية التانية: من موقع Supabase افتح **Table Editor** — هتلاقي الجداول والبيانات التجريبية قدامك.

### حاجات مهمة تعرفها

| النقطة | التفاصيل |
|---|---|
| **البيانات القديمة مش بتنتقل لوحدها** | `db:push` بينشئ **جداول فاضية**، وما بينقلش صفوف `tutor.db`. لو كنت مدخّل بيانات حقيقية محلياً، أعد إدخالها من الواجهة (أو انقلها بأدوات SQL بنفسك). **الأفضل تعمل التحويل ده قبل ما تدخل بيانات حقيقية.** |
| **الرجوع لـ SQLite** | `npm run --prefix server db:use-sqlite` وارجّع `DATABASE_URL` لسطر `file:../data/tutor.db`. |
| **احفظ التعديل في Git** | `schema.prisma` اتغيّر فعلاً — لازم تعمل commit للتغيير ده قبل ما تنشر، وإلا الاستضافة هتبني بنسخة SQLite. |
| **النسخ الاحتياطي المحلي بيتوقف** | مهمة النسخ الاحتياطي اللي بتشتغل ٢:٣٠ ص بتتخطّى نفسها بهدوء لما قاعدة البيانات مش SQLite، وبتطبع `تم تخطّي النسخ الاحتياطي — قاعدة البيانات ليست SQLite`. النسخ الاحتياطي بقى مسؤولية Supabase (متاح من **Database ← Backups**). |
| **إيقاف الباقة المجانية** | مشروع Supabase المجاني بيتوقف مؤقتاً بعد حوالي **٧ أيام من عدم الاستخدام تماماً** — يعني أسبوع كامل من غير أي طلب واحد. الاستخدام اليومي العادي بيمنع ده خالص، وحتى لو حصل بترجّعه بضغطة واحدة من لوحة التحكم. |

## ٢. رفع السيرفر

الخادم عملية Node واحدة بتستضيف الـ API والمهام المجدولة وقائمة الإرسال، **وكمان بتقدّم الواجهة نفسها** لو `web/dist` موجود. يعني **خدمة واحدة بس** هي اللي بتتنشر.

أي استضافة بتشغّل Node وبتديك دومين HTTPS هتنفع. أشهر تلاتة بباقة مجانية: **Render** (الأسهل) · **Railway** · **Fly.io**.

### الخطوات (Render كمثال — الفكرة واحدة في الكل)

1. ارفع المشروع على مستودع GitHub (خاص، عشان `.env` مش المفروض يتسرّب أصلاً — وهو مستبعَد من Git).
2. من [render.com](https://render.com): **New ← Web Service** ← اربطه بالمستودع.
3. اضبط:

   | الحقل | القيمة |
   |---|---|
   | **Environment** | Node |
   | **Build Command** | `npm install --prefix server && npm install --prefix web && npm run build` |
   | **Start Command** | `npm start` |

4. حط متغيّرات البيئة (تحت **Environment**):

   | المتغيّر | القيمة | ليه |
   |---|---|---|
   | `DATABASE_URL` | رابط Supabase الكامل مع `?sslmode=require` | مكان البيانات. |
   | `JWT_SECRET` | نص عشوائي طويل (٤٨ خانة على الأقل) | مفتاح توقيع رموز الدخول. **لو سيبته على القيمة الافتراضية أي حد يقدر يزوّر رمز دخول ويدخل كمالك.** |
   | `JWT_EXPIRES_IN` | `30d` (اختياري) | مدة صلاحية رمز الدخول. |
   | `OWNER_USERNAME` | `ahmed` أو اللي تختاره | اسم دخول المالك اللي هيتعمل مع `db:seed`. |
   | `OWNER_PASSWORD` | **كلمة مرور قوية — مش `admin123`** | كلمة مرور المالك عند الإنشاء. |
   | `CORS_ORIGINS` | `https://your-app.onrender.com` | المصادر المسموح لها بندهة الـ API. حط عنوان الخدمة نفسها، وأي عنوان تاني مفصول بفاصلة. |

   > `PORT` **متحطّهوش** — الاستضافة بتحدّده بنفسها والخادم بيقراه تلقائياً.
   >
   > عناوين `capacitor://` (تطبيق الأندرويد) وعناوين الشبكة المحلية مقبولة دايماً من غير ما تضيفها في `CORS_ORIGINS`.

5. **Deploy**. أول بناء بياخد من ٣ لـ ٧ دقايق.
6. افتح `https://your-app.onrender.com/api/health` — لازم يرد `{"ok":true}`.
7. افتح العنوان الأساسي وسجّل دخول. **غيّر كلمة المرور فوراً** من **الإعدادات ← الحساب**.

> **جهّز قاعدة البيانات قبل أول تشغيل.** لو ما نفّذتش `db:push` و `db:seed` (خطوات القسم ١) هتلاقي أخطاء «الجدول غير موجود» أو مفيش حساب تدخل بيه. الأسهل إنك تنفّذهم من جهازك وأنت مضبوط على نفس `DATABASE_URL`.

### ليه HTTPS مش اختياري

تطبيق الأندرويد **بيرفض** الاتصال بعنوان عام على `http://` عادي:

- أندرويد ٩ فما فوق بيحجب الاتصالات غير المشفّرة افتراضياً.
- إعدادات أمان الشبكة في التطبيق (`web/android/app/src/main/res/xml/network_security_config.xml`) بتسمح بـ HTTP **للعناوين المحلية بس** (زي `192.168.1.10`) وبتمنعه صراحةً على النطاقات العامة (`.com`، `.net`، `.org`، `.app` … إلخ).

يعني: **شبكة محلية → `http://192.168.1.10:4000` شغّال. إنترنت → لازم `https://`.**

الخبر الحلو إن Render و Railway و Fly بيدّوك دومين HTTPS بشهادة مجانية تلقائياً، فمفيش شغل إضافي.

### الباقة المجانية: التطبيق بينام

الخدمات المجانية **بتوقّف العملية بعد ~١٥ دقيقة من غير طلبات**، وأول طلب بعدها بياخد **٣٠ لـ ٦٠ ثانية** لحد ما تقوم تاني. أثناء النوم كمان **المهام المجدولة مش بتشتغل** (حصص اليوم، تفريغ قائمة الإرسال، التقارير الشهرية).

**الحل: نبضة كل ١٠ دقايق.** مسار `/api/health` عام ومش محتاج تسجيل دخول، فهو مثالي لكده:

1. ادخل خدمة مجانية زي [cron-job.org](https://cron-job.org) أو [UptimeRobot](https://uptimerobot.com).
2. أنشئ مهمة تنده `https://your-app.onrender.com/api/health` **كل ١٠ دقايق**.

كده الخادم يفضل صاحي طول النهار، والمهام المجدولة تشتغل في وقتها، ومفيش انتظار لما تفتح التطبيق.

> الحل ده كافي جداً لسنتر. لو النظام بقى أساسي في شغلك، أرخص باقة مدفوعة (٥–٧ دولار في الشهر) بتشيل موضوع النوم كله وبتديك أداء أثبت.

## ٣. بناء الـ APK

الناتج ملف اسمه **`StudentApp.apk`** — نسخة **debug** موقّعة بمفتاح التطوير، بتتثبّت على أي تليفون بعد السماح بالمصادر غير المعروفة، ومش صالحة للنشر على Google Play (لده شوف القسم ٦).

فيه طريقتين، والناتج واحد بالظبط.

### الطريقة (أ) — محلياً على الجهاز

**المتطلبات:** JDK **17** بالتحديد (مش ٢١ ولا ٨) + Android SDK فيه `platforms;android-34` و `build-tools;34.0.0`. السكربت بيدوّر عليهم في:

```
D:\android-tools\jdk17
D:\android-tools\sdk
D:\android-tools\gradle-home
```

الأمر:

```powershell
cd "d:\programming\mr ahmed"
npm run apk
```

بيعمل ٥ خطوات بالترتيب ويطبع كل واحدة: يتحقق من الأدوات ← يبني الواجهة (`npm run build`) ← ينسخها لمشروع الأندرويد (`npx cap sync android`) ← يجمّع الحزمة (`gradlew assembleDebug`) ← ينسخ الناتج.

**أول بناء بياخد من ٥ لـ ١٥ دقيقة** (Gradle بينزّل مكتباته أول مرة). البناءات اللي بعده أسرع بكتير.

**المتوقع في الآخر:**

```
─────────────────────────────────────────────
✔ تم بناء التطبيق بنجاح

  الملف : d:\programming\mr ahmed\StudentApp.apk
  الحجم : 4.36 ميجابايت
─────────────────────────────────────────────

  بعد تثبيت التطبيق، اكتب أحد هذه العناوين في «إعداد الخادم»:
    http://192.168.1.10:4000
```

**السطر الأخير ده مهم** — هو العنوان اللي هتكتبه في التطبيق لو الخادم شغّال على اللابتوب.

لو أدواتك في مسارات تانية:

```powershell
powershell -ExecutionPolicy Bypass -File build-apk.ps1 -JavaHome "C:\path\to\jdk17" -AndroidHome "C:\path\to\sdk"
```

ولو بتعيد المحاولة والواجهة مبنية بالفعل، وفّر وقت البناء:

```powershell
powershell -ExecutionPolicy Bypass -File build-apk.ps1 -SkipWebBuild
```

### الطريقة (ب) — GitHub Actions (من غير ما تنصّب حاجة)

لو مش عايز تنزّل ٨ جيجا أدوات أندرويد، GitHub بيبني لك في السحابة. الملف جاهز في `.github/workflows/build-apk.yml`.

**بيشتغل تلقائياً** مع أي دفعة على `main` أو `master` فيها تعديل في `web/**`، **أو يدوياً**:

1. افتح المستودع على GitHub ← تبويب **Actions**.
2. اختار **build-apk** من الجنب ← **Run workflow** ← **Run workflow**.
3. استنى ٥–١٠ دقايق.
4. افتح التشغيل، وانزل لصندوق **Artifacts**، ونزّل **`StudentApp-debug-apk`**.
5. الملف بينزل كـ `.zip` — فكّه، جوّاه **`StudentApp.apk`**.

النسخة دي متطابقة مع المحلية: نفس Capacitor 6، نفس JDK 17، نفس `compileSdk 34`، نفس `assembleDebug`. الملفات بتفضل متاحة **٣٠ يوم**.

### التثبيت على التليفون

1. **انقل الملف** للتليفون: كابل USB، أو ابعته لنفسك على واتساب/تيليجرام، أو ارفعه على Google Drive ونزّله من التليفون.
2. **افتح الملف** من مدير الملفات أو من شريط الإشعارات بعد التحميل.
3. أندرويد هيقول **«لأمانك، هاتفك غير مسموح له بتثبيت تطبيقات غير معروفة من هذا المصدر»** — ده طبيعي لأي تطبيق مش من Google Play:
   - اضغط **الإعدادات** في نفس الرسالة.
   - فعّل **«السماح من هذا المصدر»** للتطبيق اللي بتثبّت منه (Chrome أو مدير الملفات أو واتساب).
   - ارجع بزر الرجوع ← **تثبيت**.
4. لو ظهرت شاشة **Play Protect** بتقول «تطبيق غير معروف»، اضغط **تثبيت على أي حال** — الرسالة دي بتظهر لأي تطبيق مش متوزّع من المتجر.
5. هتلاقي أيقونة **«إدارة الطلاب»** في شاشة التطبيقات.

## ٤. أول تشغيل على التليفون

التطبيق مش عارف فين الخادم — لازم تقوله.

1. **افتح التطبيق.** أول شاشة هتظهر لوحدها هي **«إعداد الخادم»**.
2. **اكتب عنوان الخادم:**
   - **الخادم على لابتوبك في السنتر:** العنوان اللي طبعه `npm run dev` جنب `📱 من الشبكة المحلية`، مثلاً `http://192.168.1.10:4000`. **لازم التليفون واللابتوب على نفس شبكة الواي فاي.**
   - **الخادم على الإنترنت:** عنوان الاستضافة، مثلاً `https://your-app.onrender.com`.

   الخانة متسامحة: تقدر تكتب `192.168.1.10:4000` من غير `http://`، وتقدر تكتب الأرقام عربي (`١٩٢.١٦٨…`)، ولو لصقت `/api` في الآخر بيتشالت لوحدها.

3. **اضغط «اختبار الاتصال».** الرد بيوصل في ثواني:

   | الرسالة | المعنى |
   |---|---|
   | ✅ `تم الاتصال بالخادم بنجاح.` | تمام، كمّل. |
   | ❌ `تعذّر الوصول إلى هذا العنوان…` | الخادم مش شغّال، أو الجهازين مش على نفس الشبكة، أو العنوان غلط. |
   | ❌ `انتهت مهلة الاتصال…` | العنوان موجود بس مفيش رد — غالباً جدار حماية ويندوز بيمنع المنفذ ٤٠٠٠. |
   | ❌ `هذا العنوان يستجيب، لكنه ليس خادم النظام.` | العنوان بتاع حاجة تانية خالص (راوتر مثلاً). |

4. **اضغط «حفظ والمتابعة»** — العنوان بيتخزّن على التليفون وبيروح شاشة الدخول.
5. **سجّل دخول** بنفس بيانات الويب.

### تغيير عنوان الخادم بعدين

العنوان محفوظ على الجهاز، فمش محتاج تعيد بناء التطبيق عشان تغيّره:

- **من القايمة ← «تسجيل الخروج»**، وبعدين على شاشة الدخول اضغط رابط **«إعداد الخادم»** تحت.
- **أو** لو الاتصال قاطع أصلاً: الشريط الأصفر اللي فوق فيه رابط **«عنوان الخادم»** على طول.

في شاشة إعداد الخادم فيه كمان زر **«استخدام نفس موقع الصفحة»** لتفريغ العنوان المحفوظ (ده مفيد في المتصفح، مش في التطبيق).

> عند حفظ عنوان جديد، البيانات المخزّنة مؤقتاً من الخادم القديم بتتمسح — عشان ما تخلطش بيانات خادمين.

### لو التليفون مش شايف اللابتوب

| السبب المحتمل | الحل |
|---|---|
| مش على نفس الشبكة | اتأكد إن الاتنين على نفس الواي فاي. **بيانات الموبايل مش هتوصل للابتوب.** |
| جدار حماية ويندوز | أول مرة تشغّل الخادم بيظهر سؤال — اسمح لـ Node على **الشبكات الخاصة**. لو رفضته بالغلط، اسمح له من: لوحة التحكم ← Windows Defender Firewall ← السماح لتطبيق. |
| الشبكة معرّفة كـ «عامة» | ويندوز بيشدّد على الشبكات العامة. غيّر شبكة الواي فاي لـ **خاصة** من الإعدادات. |
| الـ IP اتغيّر | الراوتر بيوزّع عناوين متغيّرة، فعنوان اللابتوب ممكن يتبدّل بعد إعادة التشغيل. شغّل `npm run dev` وشوف السطر الجديد، أو احجز IP ثابت من إعدادات الراوتر. |

## ٥. تحديث التطبيق بعد أي تعديل

**القاعدة الذهبية:**

| نوع التعديل | محتاج APK جديد؟ |
|---|---|
| تعديل في **الخادم** (`server/**`): قواعد، حسابات، مهام مجدولة، مسارات API | ❌ **لأ.** أعد تشغيل الخادم (أو انشر من جديد) وخلاص — التطبيق بياخد السلوك الجديد فوراً. |
| تعديل في **الواجهة** (`web/src/**`): شاشات، أزرار، نصوص، ألوان | ✅ **أيوه.** الواجهة **مبنية جوّه ملف الـ APK نفسه**. |
| تعديل في **قوالب الرسائل** أو **الإعدادات** من داخل التطبيق | ❌ لأ — دي بيانات في قاعدة البيانات. |
| تغيير **عنوان الخادم** | ❌ لأ — بيتغيّر من شاشة «إعداد الخادم». |

### إعادة البناء والتثبيت

```powershell
cd "d:\programming\mr ahmed"
npm run apk
```

انقل `StudentApp.apk` الجديد للتليفون و**ثبّته فوق القديم** — أندرويد هيعرض «تحديث» بدل «تثبيت»، وبياناتك المحلية (عنوان الخادم وتسجيل الدخول) بتفضل زي ما هي، مش محتاج تكتبهم تاني.

> **مش لازم تحذف التطبيق القديم**، بشرط إن النسختين موقّعتين بنفس المفتاح. لو بنيت نسخة debug قبل كده وبعدين نسخة release (أو العكس)، أندرويد هيرفض التحديث برسالة تعارض توقيع — وقتها احذف القديم الأول.

## ٦. توقيع نسخة الإصدار (release)

نسخة الـ debug كافية تماماً للتوزيع بإيدك. النسخة دي محتاجة **بس** لو هترفع على Google Play أو عايز نسخة أصغر وأسرع بمفتاحك أنت.

**١) أنشئ مفتاح التوقيع** (مرة واحدة في العمر):

```powershell
& "D:\android-tools\jdk17\bin\keytool.exe" -genkeypair -v `
  -keystore "$env:USERPROFILE\mrahmed-release.jks" `
  -alias mrahmed -keyalg RSA -keysize 2048 -validity 10000
```

هيسألك عن كلمة مرور وبيانات بسيطة. **احفظ الملف وكلمة المرور في مكان آمن — لو ضاعوا مش هتقدر تطلع تحديث لنفس التطبيق أبداً.**

**٢) اربطه بمشروع الأندرويد:** في `web/android/app/build.gradle`، جوّه كتلة `android { }`:

```gradle
signingConfigs {
    release {
        storeFile file("C:/Users/PC/mrahmed-release.jks")
        storePassword "كلمة-المرور"
        keyAlias "mrahmed"
        keyPassword "كلمة-المرور"
    }
}
buildTypes {
    release {
        signingConfig signingConfigs.release
        minifyEnabled false
        proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
    }
}
```

**٣) ابنِ:**

```powershell
npm run --prefix web build
npm run --prefix web cap:sync
cd "d:\programming\mr ahmed\web\android"
.\gradlew.bat assembleRelease
```

الناتج في `web\android\app\build\outputs\apk\release\app-release.apk`.

> **متحطّش كلمات المرور دي في Git.** الطريقة الصح إنك تحطها في `web/android/keystore.properties` وتضيف الملف لـ `.gitignore` وتقرا منه في `build.gradle`.
> ولو هترفع على Google Play، المتجر بيطلب **AAB** مش APK: `.\gradlew.bat bundleRelease`، وكمان لازم ترفّع `versionCode` في `build.gradle` مع كل نسخة.

## ٧. الأمان

النقط دي مش رفاهية — دي بيانات طلاب حقيقيين وأرقام تليفونات أولياء أمورهم.

### ✅ اعملها قبل أي نشر

| # | الإجراء | التفاصيل |
|---|---|---|
| ١ | **غيّر كلمة المرور الافتراضية** | `admin123` مكتوبة في ملف عام في المشروع. أول ما تدخل: **الإعدادات ← الحساب** ← غيّرها لكلمة مرور طويلة مش مستخدمة في أي مكان تاني. |
| ٢ | **حط `JWT_SECRET` عشوائي وطويل** | ده مفتاح توقيع رموز الدخول. طول ما هو `change-me-to-a-long-random-string`، **أي حد يعرف الكود يقدر يزوّر رمز دخول ويدخل كمالك**. ولّد واحد: <br>`-join ((48..57) + (65..90) + (97..122) \| Get-Random -Count 48 \| ForEach-Object { [char]$_ })`<br>وحطه في `JWT_SECRET`. تغييره بيخرّج كل الأجهزة، فكل واحد هيسجّل دخول من تاني — وده متوقّع ومطلوب. |
| ٣ | **متحطّش `.env` في Git أبداً** | `server/.env` مستبعَد في `.gitignore` — سيبه كده. لو اتسرّب مرة، غيّر `JWT_SECRET` وكلمة مرور قاعدة البيانات فوراً؛ مسح الملف من الـ commit **مش** كافي لأنه بيفضل في تاريخ Git. متكتبش أسرار في issues أو في لقطات شاشة كمان. |
| ٤ | **HTTPS للعناوين العامة** | مذكورة فوق كمتطلب تقني لأندرويد، وهي كمان متطلب أمني: على HTTP عادي رمز الدخول وكل بيانات الطلاب بتمشي على الشبكة **مقروءة**. |
| ٥ | **اضبط `CORS_ORIGINS`** | حط عنوان تطبيقك بس. |
| ٦ | **كلمة مرور مستقلة لكل مساعد** | متديش حد بيانات حساب المالك. اعمل له حساب **مساعد** من صفحة **المستخدمون** — كده تقدر توقفه في أي وقت، وسجل النشاط يفضل واضح مين عمل إيه. |
| ٧ | **راجع سجل النشاط من وقت للتاني** | خصوصاً فلتر **نوع الإجراء = حذف**. |
| ٨ | **خد نسخ احتياطية بره الجهاز** | محلياً: انسخ `server\backups\` على فلاشة أو Drive. على Supabase: **Database ← Backups**. |

### ⚠️ خطر Green API — اقرأه قبل ما تفعّله

**Green API بوابة غير رسمية.** هي بتتصرّف كأنها جهاز مرتبط بواتساب بتاعك، وده **مخالف لشروط استخدام واتساب**. النتيجة الواقعية: **فيه احتمال حقيقي إن رقمك يتحظر** — مؤقتاً أو نهائياً — خصوصاً لو الرسائل كتيرة أو ولي أمر بلّغ عنها كسبام.

- **جرّب على رقم تاني**، مش رقمك الأساسي اللي شغّال بيه.
- خلّي **ساعات الهدوء** شغّالة وسيب حجم الإرسال في حدود المعقول.
- **`WA_LINK` (الوضع الافتراضي) آمن ١٠٠٪** — الإرسال بيتم من واتساب بتاعك بإيدك زي أي رسالة عادية، ومفيش أي خطر حظر. لو مش متأكد، سيبه.
- البديل الرسمي المعتمد لو الشغل كبر هو **Twilio (WhatsApp Business API)** — مدعوم في نفس الشاشة، بس محتاج حساب أعمال معتمد ومصاريف شهرية.

### ملاحظات على وضع التطوير

الإعدادات دي مقصودة للتجربة على الشبكة المحلية، ولو نقلت لخادم HTTPS ثابت يُفضّل تشدّها:

- `web/capacitor.config.ts` فيه `server.cleartext: true` و `android.allowMixedContent: true` عشان الاتصال بـ `http://192.168.x.x` يشتغل. أول ما يبقى للخادم عنوان HTTPS ثابت، رجّعهم `false` وامسح استثناءات `network_security_config.xml`، وأعد البناء.
- `VITE_API_BASE` في `web/.env.production` سايبة فاضية عمداً، عشان كل معلّم يكتب عنوان خادمه من داخل التطبيق. لو عندك عنوان ثابت لكل الأجهزة، حطه هناك وشاشة «إعداد الخادم» تبقى غير ضرورية (بتفضل متاحة للتغيير).
